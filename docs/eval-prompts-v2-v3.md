# v2 / v3 提示词真实模型评测

> **结论**：v3 在**格式合规**上明显好于 v2（违规数 0.93 → 0.07），**旁路稳定产出**（14/14 可解析），书级关联分析**不输且略占优**（3 胜 0 负 2 平）；
> 章节总结的**质量**没有可靠差异（评判者位置偏向严重，只剩弱信号：4 胜 3 负 6 平）。
> 规格的回退条件是「v3 格式违规率高于 v2」——**没有触发**。但这是**小样本、单一模型家族、同族评判**，不足以宣称 v3 质量更好。

## 评测设置

- 脚本：`tests/tour/eval_prompts.py`（CLI 同一套提示词模板 v2 / v3，同章节各生成一次）
- 生成：`glm-5.3-flash`（智谱 Coding Plan 网关；思考深度 medium；输出上限取模型元数据 `meta.output = 131072`，不手写）
- 评判：`glm-5.3`，**每对用两种顺序各评一次，只有两次一致才算数**（不一致记 tie 并统计一致率）
- 样本：5 本书 × 3 章 = 15 章（1 章被智谱内容安全过滤拦下，记为失败；1 章 v2 退化输出被排除）→ **14 章入统计、5 本书级对比**。全是中文非虚构，EPUB
- 指标：
  - 规则项（与位置无关，可信）：标题 / 分割线 / `***` / 加粗 >6 / 问候语 各记 1 次违规
  - v3 旁路：标记是否出现、JSON 是否可解析、实体数、别名数
  - 盲评：章节总结、书级「章节关联分析」（v3 额外带实体表）

## 结果

| 指标 | v2 | v3 |
|---|---|---|
| 平均违规数（越低越好） | 0.93 | **0.07** |
| 平均正文长度（字） | 2267 | 1810（−20%） |
| 平均加粗数 | 3.64 | 3.86 |
| v3 旁路可解析率 | — | **14/14** |
| v3 平均实体 / 别名 | — | 8.9 / 5.9 |

| 评判（两种顺序一致才算） | v2 胜 | v3 胜 | 平 | 跳过 | 两次一致率 |
|---|---|---|---|---|---|
| 章节总结（14） | 3 | 4 | 6 | 1 | **54%** |
| 书级关联分析（5） | 0 | **3** | 2 | 0 | 80% |

## 怎么读这些数字

**可信的**

- 违规数、旁路解析率：确定性规则，不依赖评判者。v3 的差距（0.93 → 0.07）在每一本书上都同向。
- v3 的元数据旁路在这个模型上稳定（14/14），包括此前 MiniMax 上两次失败的那一章（见下「MiniMax 的信号」）。

**要打折的**

- **评判者有严重的位置偏向**。第一轮「v3 随机换位、各评一次」的结果是 v2 6 : v3 7 : 平 1，但拆开看：v3 排 A 位时只赢 2/8，排 B 位时赢 5/6，
  **B 位整体胜出率约 79%**——那组数字基本是噪声。改成两种顺序各评一次后，章节级只有 54% 的配对结论一致，其余 6 对记为平。
- **长度混杂**：v3 平均短 20%。评判维度包含「覆盖」，偏好长文的评判者会压低 v3；反过来 v3 的「可读」优势也可能被算进去。无法分离。
- **同族评判**：生成 `glm-5.3-flash`、评判 `glm-5.3`，有自评偏向的可能；换成另一家模型（MiniMax / DeepSeek）做评判能验证，但这次可用的网关额度不够。
- **样本小**：14 章 / 5 本，且全是中文非虚构；小说（`fiction` 模板）、PDF、英文书没有覆盖。
- `meta_ok` 只衡量「能解析」，不衡量实体是否准确。
- 书级关联分析 3:0 是目前最像样的质量信号（80% 一致），但 n=5。

## 一个异常样本

有一章的 v2 输出只有 **4 个字符**（模型自身故障，不是提示词的问题）。第一轮评测里它被记成「v3 获胜」。脚本现在把任一版本正文 <200 字的视为退化输出、不参与评判。

## MiniMax 的信号（此前，样本极小）

MiniMax-M3.1-Flash 只跑了 2 章就触发 Token Plan 用量上限，数据无统计意义。唯一值得记的是：最长的一章（8123 字）v3 旁路两次都失败
（一次漏写标记、一次 JSON 不合法）。**换成 GLM 后同一章的旁路解析成功**，所以更可能是模型 / 长度相关而非提示词的普遍问题——
但只有一个对比点。`split_chapter_meta` 在解析失败时正文照常保留，后果是「没有实体旁路」，不是内容损坏。

## 还没验证的

1. 换一家模型做评判，看章节级一致率能否明显提高。
2. 小说模板、PDF、英文书。
3. 把 v3 加长一点（或评判时控制长度）后质量判断是否变化。
4. 其他生成模型上旁路的稳定性（尤其长章节）。
5. 评测输出已保存正文（`results.json` 的 `text` 字段），可以人工抽查几对。

## 复现

脚本默认读 `.env` 的 `VITE_TEST_LLM_*`；进程环境变量优先（密钥可只放内存）。输出上限用模型元数据传入，不手写：

```bash
VITE_TEST_LLM_BASE_URL=https://open.bigmodel.cn/api/coding/paas/v4 \
VITE_TEST_LLM_API_KEY=*** \
VITE_TEST_LLM_OUTPUTS='{"glm-5.3-flash":131072,"glm-5.3":131072}' \
uv run --no-sync --with ebooklib --with pyyaml --with pypdf python tests/tour/eval_prompts.py \
  --model glm-5.3-flash --judge-model glm-5.3 \
  --epubs "C:/Users/PC/Documents/Epub/EBooks/_epub_processed/release-ready" --books 5 --per-book 3 --out .tmp/eval-glm
```

- 思考型模型每次调用要数十秒到数分钟；全量约 45 分钟、43 万 token。
- 默认发 `reasoning_effort: medium`（智谱网关接受）；`--no-effort` 在网关不接受该参数时用；`--sensenova` 改走 SenseNova 网关。
- 智谱网关偶尔会触发内容安全过滤（HTTP 400 / 1301），脚本按单章失败记录并继续。
