# v2 / v3 提示词真实模型评测（未完成）

> 结论先行：**这次评测没有得出可用结论**。样本只有 2 章，之后触发了模型服务的用量上限。
> 规格要求的「评测达标前不切默认」门槛**仍未满足**；v3 目前作为默认，依据仍只是"旁路损坏时退化为无旁路"的鲁棒性。

## 做了什么

- 脚本：`tests/tour/eval_prompts.py`（CLI 同一套提示词模板 `PromptTemplates` v2 / v3，同章节各生成一次）
- 模型：`MiniMax-M3.1-Flash`（OpenAI 兼容网关）。推理型模型，思考计入 `max_tokens`，所以用 24000 + `reasoning_effort:"low"`
- 指标：
  - 规则项：标题 / 分割线 / `***` / 加粗过多（>6）/ 问候语 → 记为"违规"，数得越少越好
  - v3 旁路：标记是否出现、JSON 是否可解析、实体数、别名数
  - 盲评：同一模型做 A/B 随机换位的两两评判（章节级、书级关联分析）
- 计划规模 4 本 × 3 章；实际完成 2 章 / 0 本书级对比。

## 实际发生的事

| 阶段 | 结果 |
|---|---|
| 冒烟（1 本 2 章） | 完成，耗 8.9 万 token |
| 全量第 1 本前 2 章 | 完成 |
| 全量第 1 本第 3 章起 | HTTP 429：`Token Plan 用量上限`；之后网关 503 `auth_unavailable`，其余 10 次调用全部失败 |

按"重试前先说明改变了什么"的约定：用量上限不是代码问题，原样重试只会继续失败并烧请求，所以**没有重试**。

### 改用 SenseNova 网关的尝试（同样失败）

MiniMax 用完后改用 `gen-image-sensenova` skill 配置的 SenseNova 网关（`--sensenova`，可选文本模型：
`deepseek-v4-flash` / `glm-5.2` / `sensenova-6.8-flash-lite` / `kimi-k3` 等）。结果：

- 第一轮：`sensenova-6.8-flash-lite` 单次探测成功，之后同模型、同参数连续 429（`inference exceeds tpm/rpm limit`）；`kimi-k3` 报 `EndpointTPMExceeded`
- 脚本原先对 HTTP 错误**不等待**就重试，三次请求瞬间打完——这是脚本缺陷，已改成对 408/429/5xx 做 20s×n 退避（Token Plan 用量上限类 429 不再重试）。退避后整轮仍全部 429
- 最后探测：`deepseek-v4-flash`、`glm-5.2` 也返回 `insufficient_quota`。这把 key 的额度很小（疑似为生图配置），撑不起约 50 万 token 的评测

结论：两个网关当前都没有足够额度，**没有再继续重试**。

## 唯一值得跟进的信号：v3 旁路在长章节上脆弱

同一章（原文 8123 字，样本里最长）在两次运行中**两次旁路都失败，但形态不同**：

- 冒烟：模型没有输出 `<!--juhua:meta-->` 标记
- 全量：标记输出了，但 JSON 解析失败

另一章（3923 字）两次都成功（11 个实体）。这与"章节越长，模型越容易漏写或写坏结尾的机器可读块"的猜测一致，
但**只有 1 个对比点，不能确认**。当时脚本没保存原文，所以不知道是被截断、带了代码围栏还是 JSON 里有未转义的引号。

好在失败的后果是已知的：`split_chapter_meta` 解析失败时正文照常保留、只是没有实体旁路（由 `chapterMeta` 契约样例覆盖）。
即这是"体验退化"，不是"内容损坏"。
