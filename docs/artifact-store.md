# 产物持久化与清理

> 原则：**花钱生成的、或用户亲手写的东西，不能只存在一台设备的浏览器里**；每份产物要能回答三个问题——存在哪、什么时候算过时、过时了怎么处理。允许不兼容旧作品（旧格式由「清理」收走，不做迁移）。

## 1. 现状与判断

| 产物 | 现在存在哪 | 判断 | 处理 |
|---|---|---|---|
| 章节总结 + 关联 + 全书综述 | WebDAV `{名}-完整摘要.md`（头部 HTML 注释元数据）；本机 IndexedDB 章节缓存（键含文件指纹 / 内容 / 模型 / prompt / 语言） | 合理。缓存键已包含全部输入，换模型 / prompt 自动失效 | 保持；MD 仍是人可读的导出 |
| 关键图表 | WebDAV `{名}-完整摘要.json` | 合理 | 保持 |
| v3 章节旁路（别名等） | WebDAV `{名}-完整摘要.meta.json` | 合理 | 保持 |
| 速读 / 自测 / 答题记录 | WebDAV 信封 `.juhua/books/<bookFolder>/study.json.gz`（速读、自测、答题同一封装）；本机 IndexedDB `juhua-study` 作缓存 | ✅ 已实现（§2）：换设备不再重新付费生成 | 保持；过时只标注不删 |
| 笔记（划线 / 批注） | WebDAV 信封 `.juhua/books/<bookFolder>/notes.json.gz` + 人可读副本 `{名}-笔记.json`；本机 IndexedDB `juhua-notes` | ✅ 已实现（§2）：条目级合并 + 墓碑，本机为准 | 保持；含用户数据，清理默认不碰 |
| 问书对话 | 内存 | ✅ 有意不持久（一次性问答，答案依据可再现） | 保持 |
| 书库索引 / 封面 | WebDAV `.juhua/library.json.gz`；KV 云端书目 | ✅ 已按「云端为主数据」重做并审查过 | 保持（见 covers- kv.md） |
| 处理历史 / 用量 | 共享状态 KV（追加型分区） | ✅ | 保持 |

## 2. 统一信封（已实现）

速读 / 自测 / 笔记各存一个文件：`{syncPath}/.juhua/books/<bookFolder>/<kind>.json.gz`（gzip 的 JSON），三者是**同一种信封**：

```jsonc
{
  "schema": 2,                 // 不兼容升级就加一；读到更高版本的文件只读不写（绝不覆盖）
  "kind": "study" | "quiz" | "notes",
  "bookKey": "书名|作者",       // 稳定书身份：只由书名 + 作者决定，与内容无关
  "title": "…", "author": "…",  // 便于人肉排查；author 可能缺省
  "inputsFp": "…",             // 上游指纹：速读 / 自测 = 各章总结的指纹（studyKeyOf）；笔记 = 空
  "chapterCount": 12,
  "model": "…", "promptVersion": "…",   // 仅 AI 产物
  "createdAt": 0, "updatedAt": 0,
  "data": { }
}
```

- **书身份与目录名**：`bookKey = "{书名}|{作者}"`（**不是**内容指纹——否则重新生成总结就会换目录，旧目录无人认领）；目录名 = 清洗掉 `\ / : * ? " < > | %` 与控制字符后的书名（截 48 字）+ `~` + `bookKey` 的 FNV-1a 哈希，既可读又不会撞（清洗掉 `%` 是为了让清理侧能放心拒绝「百分号编码过的目录名」）。实现见 `src/services/artifacts/envelope.ts`。
- **过时判定**只有一个：上游指纹 ≠ 当前上游指纹（任一方缺失则不判）。速读与自测**各记自己的指纹**（`kitFp` / `quizFp`）：只重生成速读时，自测仍按旧总结算过时，界面按面板分别提示；信封上的 `inputsFp` 只有两份都跟上当前总结才写当前值，否则保留旧值（别的设备和清理侧据此判过时）。过时的产物**不自动删**，也不当成新的：界面上标注「按旧总结生成」，自动生成时按当前总结重做一次；清理里单列为「已过时」。
- **读**：本机先显示 → 异步读云端信封 → 按份合并（生成物按 `updatedAt` 取新、空缺由另一份补上；答题**只在两边题目完全相同时**按 id 取并集，题目换过就只认题目来源那一侧的答案）→ 合并结果与本机不同就刷新界面，与云端不同就写回。
- **写**：本机立即写（IndexedDB），云端异步防抖写（`study` 2 秒、`notes` 3 秒）；失败只记 `logger.warn` 并留在待写队列（下次改动或换书时补推），离线照常可用。
- **绝不覆盖云端**的三种情形：①读到 `schema` 更高的信封 → 界面提示「云端那份来自更新的版本」，只读；②信封结构读不懂；③这一轮读取失败（网络抖动 / 5xx）。后两种按「云端暂不可用」处理，本机内容照常但一封都不写出去（笔记连人可读副本也不写，免得两份互相矛盾）。只有确知「云端还没有这份存档」（`missing`）时，才把本机已有内容推上去。
- **笔记合并**：条目级 `id + updatedAt`，同 id 取较新者、相等保留本机；删除写墓碑（`deleted: true`，30 天后丢弃），否则旧副本会把它复活。UI、Markdown 导出与人可读副本只消费 `visibleNotes`；载荷版本（`NotesFile.version`）比本机认识的新时同样只读不写。
- 读不懂的信封（`schema` 更高 / 结构坏 / JSON 不合法）：当作不存在，不覆盖、不报错、不删除。
- 代码坐标：信封与 IO 在 `src/services/artifacts/`（`envelope.ts` 纯函数、`io.ts` 走 `webdavService` + `gzipText`）；接入点 `src/study/studyStore.ts`（速读/自测/答题）与 `src/notes/notesStore.ts`（笔记）。

## 3. 过时产物的清理（已实现）

入口：设置 → 书库 →「清理过时产物」（`ArtifactCleanup` + `artifactCleanup*.ts`）。

| 类别 | 判定 | 默认 |
|---|---|---|
| 旧版格式 | `{名}_chapter_N_summary.md`、`_chapter_N_mindmap.json`、`_combined_mindmap.json`：早已被「完整摘要」取代 | 勾选 |
| 悬空附件 | `-完整摘要.json` / `.meta.json` 的主 MD 已不存在，单独读不出来 | 勾选 |
| 书已不在 | 主 MD 在，但对应的书既不在 WebDAV、也不在云端书目（它的附件一并列出，保持成套） | **不勾选**：摘要仍可读，是否保留由用户定 |
| 已过时 | 信封 `inputsFp` 与索引里该书「当前各章总结指纹」不同：速读 / 自测是按旧总结生成的 | **不勾选**：重新生成即可覆盖，且同一封装里还带着答题记录 |
| 整包 | `.juhua/books/<bookFolder>` 对应的书已不在书库 | **不勾选**：可能含笔记等用户数据，列出时额外警示 |

安全闸（沿用云端书架审查的结论）：

1. 打开即**强制重扫**，扫描失败 / 同步目录里一本书都没扫到（多半目录配错）→ 拒绝给清单，什么都不删；
2. 「书还在」= WebDAV 真书 **∪** 云端书目里的记录，任一有就不算「书已不在」；
3. 只看同步目录之下、且命名严格匹配的产物文件；书籍文件、其它命名的文件**永不进入清单**；`.juhua` 下只按明确的信封归类（信封必须能解析、版本认识、且索引里有可比对的指纹）才列出；删整包时目录名要能通过「解码后仍不含 `/` `\` `%`、不是 `.` / `..`、且严格在当前同步目录的 `.juhua/books/` 之下」的校验，文件项也要求落在当前同步目录内，不通过一律拒绝删除；
4. 删除前二次确认；并发 3，单个失败不影响其余，结果逐项回报。

「当前指纹」从哪来：书库索引**不存**章节总结，所以打开一本书时（store 绑定该书）会把 `studyKeyOf(book)` 顺手记进索引条目 `studyFp`；清理时用信封的 `inputsFp` 与它比对（整包「书已不在」按书名比对，书名相同作者不同时两者都非空就不认作同一本；「已过时」只认书名 + 作者都一致的精确匹配）。索引里没有 `studyFp` 的书一律**不判过时**（宁可不判，也不误删）。
