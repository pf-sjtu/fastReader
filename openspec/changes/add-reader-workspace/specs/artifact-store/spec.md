# artifact-store Delta

## ADDED Requirements

### Requirement: 产物信封
花钱生成的产物（速读、自测）与用户亲手写的数据（笔记、答题）MUST 以统一信封持久化到 `{syncPath}/.juhua/books/<bookFolder>/<kind>.json.gz`（`kind` ∈ `study` | `quiz` | `notes`），gzip 压缩的 JSON，字段为 `schema`、`kind`、`bookKey`、`title`、`author`、`inputsFp`、`chapterCount`、`model`、`promptVersion`、`createdAt`、`updatedAt`、`data`。读取方 MUST 容忍更高的 `schema`：只读不写、绝不覆盖；解析失败或字段不合法的信封 MUST 当它不存在（不覆盖、不报错、不删除）。

#### Scenario: 速读、自测与笔记各自落盘
- **WHEN** 用户生成速读包、生成自测并答题、或写笔记
- **THEN** 对应信封写到同一本书目录下的 `study.json.gz` / `quiz.json.gz` / `notes.json.gz`

#### Scenario: 云端信封来自更新的版本
- **WHEN** 读到的信封 `schema` 高于本版本认识的值
- **THEN** 该信封保持只读，本机不覆盖它，界面上说明"云端那份来自更新的版本"

#### Scenario: 信封损坏
- **WHEN** 信封不是合法 JSON 或缺少必要字段
- **THEN** 视为不存在，本机数据照常使用，且不删除该文件

#### Scenario: 这一次没读成
- **WHEN** 读取云端信封失败（网络错误、服务端 5xx 等无法判定文件是否存在）
- **THEN** 当作"云端暂不可用"：本机照常用，但不得把本机内容写上去覆盖云端，界面说明"这次只保存在本机"

### Requirement: 稳定书身份与上游指纹
信封的目录 MUST 由稳定书身份 `bookKey = "{title}|{author}"` 决定（不含内容指纹），目录名为清洗掉 `\ / : * ? " < > | %` 与控制字符后的书名加 `~` 加 `bookKey` 的哈希；产物的上游版本 MUST 记在 `inputsFp`：速读与自测为"各章总结指纹"，笔记为空。速读与自测 MUST 各自记住自己那一份的指纹，信封上的 `inputsFp` MUST 只在两份都等于当前指纹时才写当前值，否则 MUST 保留旧值。**过时判定 MUST 只有一条**：该份的指纹与当前指纹不同，任一方缺失时 MUST 不判过时。

#### Scenario: 重新生成章节总结
- **WHEN** 各章总结被重新生成，指纹随之变化
- **THEN** 信封仍在原目录，`inputsFp` 与当前指纹不符，该产物被标注为"按旧总结生成"

#### Scenario: 只重生成速读
- **WHEN** 只把速读包按当前总结重新生成，自测仍是上一轮的
- **THEN** 速读面板不再提示过时，自测面板仍然提示，信封 `inputsFp` 保持旧值

#### Scenario: 另一台设备打开同一本书
- **WHEN** 另一台设备（书名、作者相同）打开这本书
- **THEN** 算出同一个 `bookKey` 与同一个信封路径，读到同一份产物

### Requirement: 本机优先的跨设备读取与合并
打开书时 MUST 先显示本机数据，再异步读云端信封并按 `updatedAt` 做合并；合并结果与本机不同 MUST 刷新界面，与云端不同 MUST 以防抖（速读 / 自测 2 秒、笔记 3 秒）写回云端。答题记录 MUST 只在两边的题目完全相同（题目内容一致）时才按题目 id 取并集，题目换过时 MUST 只保留题目来源那一侧的答案。写入失败 MUST 不影响本机使用（只记日志）并 MUST 留在待写队列等下一次改动或换书时补推。只有确知云端还没有这份存档时，MUST 把本机已有内容推上去；读失败、读不懂或版本更高时 MUST 一封都不写。云端不可用或写入失败 MUST 让用户看见"这次只保存在本机"。

#### Scenario: 两台设备各写一半
- **WHEN** 甲设备只有速读包，乙设备只有自测题，两者上游指纹相同
- **THEN** 合并后两边都保留，并把补齐后的结果写回云端

#### Scenario: 云端较新
- **WHEN** 云端信封的 `updatedAt` 比本机新且上游指纹相同
- **THEN** 生成物以云端为准，两边题目相同时答案取并集

#### Scenario: 云端信封版本更高时本机编辑
- **WHEN** 读到的信封 `schema` 更高，之后用户又改了本机数据
- **THEN** 本机数据照常保存与展示，但云端那份 MUST 原样不动

#### Scenario: 换设备前一直离线
- **WHEN** 本机已有离线生成的速读包，云端还没有这份存档
- **THEN** 打开书后本机内容被推上去，另一台设备能看到它

#### Scenario: 离线编辑
- **WHEN** WebDAV 未启用或连接失败
- **THEN** 本机照常保存与展示，界面标注云端暂不可用，不反复打扰用户

### Requirement: 笔记条目级合并与墓碑
笔记 MUST 以条目为单位合并：同 `id` 取 `updatedAt` 较大者，相等保留本机；不同 `id` 取并集。删除 MUST 写墓碑（`deleted: true`）而不是物理删除，墓碑 MUST 保留 30 天后丢弃；墓碑 MUST 不出现在界面、导出与 `{name}-笔记.json` 可读副本中。可读副本 MUST 继续按 3 秒防抖写出，只含可见笔记；信封写失败时 MUST 不写副本，并把这次改动留在待写队列。笔记载荷自身的版本比本机认识的新时 MUST 视为只读（不覆盖、不写副本）。

#### Scenario: 两端各改同一则笔记
- **WHEN** 甲设备与乙设备都改了同一条笔记，甲的时间戳更新
- **THEN** 合并结果采用甲设备的正文

#### Scenario: 一端删除
- **WHEN** 甲设备删除了一则笔记，乙设备还留着它
- **THEN** 合并后该笔记为墓碑状态，界面与导出都看不到它

#### Scenario: 墓碑过期
- **WHEN** 墓碑存在超过 30 天
- **THEN** 它在后续清理中被丢弃

#### Scenario: 写入失败后不丢改动
- **WHEN** 云端写入失败（网络中断），之后用户在另一本书上触发同步
- **THEN** 之前失败的那本书的改动被再次尝试写出

### Requirement: 过时产物识别与清理
清理功能 MUST 覆盖五类产物：旧版格式（`_chapter_N_summary.md` 等）、悬空附件（主摘要不在）、书已不在（同步目录下旧命名的产物）、信封"已过时"（该份指纹与索引中该书当前指纹不符）、`.juhua/books` 下书已不在的整包。清理 MUST 保留四条安全闸：强制重扫、扫描失败或扫到 0 本书时拒绝给出清单、"书还在"取 WebDAV 真书与云端书目的并集、删除前二次确认且并发不超过 3；删除前 MUST 再次校验目标路径，不通过则拒绝并逐项报告。

#### Scenario: 总结换了以后
- **WHEN** 某本书的信封 `inputsFp` 与索引里记录的当前指纹不同
- **THEN** 清理列出该信封为"已过时"，并默认不勾选

#### Scenario: 书已不在书库
- **WHEN** `.juhua/books/<folder>` 对应书名与作者都不在"书还在"集合中
- **THEN** 该整包列为"书已不在"，默认不勾选；若包含笔记则额外警示

#### Scenario: 无法判断时不动
- **WHEN** 索引里没有这本书的指纹，或信封版本高于本版本
- **THEN** 清理不列出该产物

#### Scenario: 删除前的路径校验
- **WHEN** 清理准备删除一个整包目录或文件项
- **THEN** 整包目录名解码后不含 `/` `\` `%`、不是 `.` / `..`，且严格位于当前同步目录的 `.juhua/books/` 之下；文件项位于当前同步目录之下；不通过则拒绝删除并逐项报告失败

#### Scenario: 默认勾选
- **WHEN** 清理生成清单
- **THEN** 只有旧版格式与悬空附件默认勾选；"已过时"与整包默认不勾选；含笔记的包一律不默认勾选并显示"不可恢复"警示；信封 `schema` 更高或索引里没有该书指纹的产物不列入清单

#### Scenario: 书名匹配的边界
- **WHEN** 整包与书库里的书书名相同但两侧作者都非空且不同
- **THEN** 不认作同一本，该整包按"书已不在"处理；"已过时"只认精确 `bookKey`
